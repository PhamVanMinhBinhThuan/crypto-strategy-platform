# F-013 UI Reference Mapping

## Feature

F-013 owns Experiment, Result and Leaderboard browser UI on top of F-011 frontend foundation.

## UI-03 — Backtest Results

- Screenshot: `../screens/Backtest Results.png`
- Page source: `../prototype/pages/BacktestResultsPage.tsx`
- Components: `../prototype/components/backtest/`
- Production route: `/backtests`

### Reference intent

- result/provenance header;
- metric-card hierarchy;
- trade history table;
- analytical chart/equity presentation;
- dense but readable result workspace.

### Contract guardrails

The current released public Backtest Result representation supports four primary metrics:

- Total Return
- Win Rate
- Maximum Drawdown
- Number of Trades

If the prototype shows Profit Factor, Sharpe Ratio or other values not supplied by a released public contract, F-013 must not calculate them in the browser. Omit them or record an upstream contract gap.

Trade rows should display authoritative public result fields. Do not re-run Backtest or recompute financial outcomes in React.

## UI-04 — Search & Leaderboard

- Screenshot: `../screens/Search & Leaderboard.png`
- Page source: `../prototype/pages/SearchLeaderboardPage.tsx`
- Components: `../prototype/components/search/`
- Production route: `/search`

### Reference intent

- Search/Experiment configuration placement;
- lifecycle/progress visualization;
- current/best status presentation;
- Leaderboard Top-K hierarchy;
- realtime revision/update affordance.

### Contract guardrails

- Search execution belongs to F-010, not React.
- Start/Stop/Reproduce are public REST commands when released; business mutation is not performed over WebSocket.
- Pause/Resume must not become functional production controls unless F-009/F-010 publishes those commands.
- Worker-monitor or stage simulation in the prototype is presentation-only unless the public API actually exposes equivalent authoritative state.
- Leaderboard columns must map to released public fields. The browser must not synthesize Return, Win Rate, Sharpe, Trades or ranking values absent from the contract.
- REST/durable snapshot remains authoritative; realtime events improve freshness and must tolerate duplicates, stale delivery, reconnect and snapshot recovery.

## Dependency gate

F-013 Start/Reproduce/Search-progress completion depends on the released F-010 Search Coordinator/public integration. If that dependency is unavailable, fixture/read-only UI work may proceed through F-011 test adapters, but production E2E must remain dependency-blocked rather than simulated.
